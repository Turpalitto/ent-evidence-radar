# Политика безопасности

## Как сообщить об уязвимости

Откройте приватный security advisory в GitHub (**Security → Report a vulnerability**) или
напишите владельцу репозитория. Пожалуйста, не публикуйте детали в открытых issue до исправления.
Исправления безопасности выходят патч-релизами и отмечаются в `CHANGELOG.md`.

## Модель угроз

Приложение — персональный/командный «радар» публикаций. Данные в нём не являются
персональными данными пациентов, но ценны пользователю (закладки, заметки, правки, настройки)
и стоят денег (вызовы ИИ-провайдера, лимиты NCBI). Защищаем от:

| Угроза | Защита |
| --- | --- |
| Посторонний меняет данные или настройки, запускает обновления, тратит ИИ-бюджет | Все изменяющие и дорогие маршруты требуют авторизации (`checkApiAuth`): Bearer / `X-API-Key` = `API_SECRET` для скриптов и cron, либо подписанная сессионная cookie после `/login`. Без `API_SECRET` приложение считается работающим в доверенной сети и открыто (об этом предупреждает лог и экран диагностики) |
| CSRF от имени залогиненного пользователя | Cookie `ent_radar_session` — `httpOnly`, `SameSite=Lax`, `Secure` в проде. Для изменяющих методов с cookie дополнительно требуется same-origin (`Sec-Fetch-Site: same-origin` или совпадающий `Origin`), иначе 403. Для Bearer-токена проверка не нужна — браузер его не подставит сам |
| Перебор пароля / токена | Общий кросс-инстансный rate-limit (таблица `rate_limits`): вход — 10 попыток за 10 мин с IP; `/api/ai` — 30/мин; `/api/refresh` — 5/мин. Сравнение секретов — `timingSafeEqual` |
| Подделка IP для обхода лимитов | Заголовкам прокси по умолчанию **не доверяем**; `TRUST_PROXY=1` (+ `TRUSTED_PROXIES`, `CLIENT_IP_HEADER`) включайте только за своим обратным прокси |
| XSS / внедрение скриптов | CSP с одноразовым nonce и `strict-dynamic` (`src/proxy.ts`), `frame-ancestors 'none'` + `X-Frame-Options: DENY`, `object-src 'none'`. Шрифты локальные, внешних скриптов нет. Контент источников рендерится как текст, в Atom-ленте экранируется |
| Внедрение формул через экспорт | CSV экранирует ячейки, начинающиеся с `= + - @` |
| Инъекции в SQL / FTS | Только параметризованные запросы drizzle; поисковые термы оборачиваются в кавычки для `websearch_to_tsquery`, кавычки внутри удаляются |
| Неконтролируемый расход внешних API | `POST /api/ai` принимает только `{articleId, action}` — текст берётся из базы; суточный бюджет `AI_DAILY_BUDGET` и семафор `AI_MAX_CONCURRENCY` хранятся в БД (общие для инстансов); таймауты простоя и общего времени стрима |
| Отказ в обслуживании запросами к БД | Лимиты на размер страниц (`pageSize ≤ 200`), экспорт ≤ 2000 записей, массовые операции ≤ 200 id, ограничение числа концепт-групп и синонимов в поиске, zod-валидация всех тел запросов. Публичные читающие маршруты — мягкий in-memory rate-limit (`src/lib/public-api.ts`): `/api/articles` и `/api/articles/:id/related` — 240 запросов/мин на клиента, `/feed.xml` — 60 за 10 мин; клиент = сессия → токен → IP. Без `TRUST_PROXY` анонимные клиенты неразличимы, и действует общий предохранитель ×10 — за прокси включайте `TRUST_PROXY=1`, чтобы лимит стал поклиентским |
| Потеря данных | Миграции под advisory-lock с pre-migration снимком; PGlite не сбрасывается при повреждении без явного `PGLITE_RESET_ON_FAILURE=1`; автобэкапы `AUTO_BACKUP_HOURS` с ротацией; восстановление — слияние, а не перезапись |
| Утечка секретов через диагностику | `GET /api/admin/diagnostics` отдаёт только **факт** наличия переменных окружения, без значений; ошибки 500 содержат `requestId`, а не стек |
| Уязвимые зависимости | CI: `npm audit --omit=dev --audit-level=high` блокирует сборку; Dependabot еженедельно; Docker-образ работает от непривилегированного `uid 1001` |

Что **не** входит в модель: защита от администратора с доступом к серверу/БД, шифрование БД
на диске, многопользовательские роли (в приложении одна роль — «владелец»).

## Сессии и секреты

- `API_SECRET` — пароль входа и токен для API. `SESSION_SECRET` (если задан) подписывает cookie;
  иначе используется `API_SECRET`. Токен сессии `v1.<exp>.<nonce>.<hmac-sha256>` не содержит секрета;
  срок — 30 дней. **Смена `SESSION_SECRET` мгновенно отзывает все сессии.**
- Секреты читаются только из окружения; в репозитории — лишь `.env.example`. Не коммитьте `.env`.
- В логах (`LOG_LEVEL`) не печатаются ни токены, ни тела запросов.

## Безопасное развёртывание — чек-лист

1. Задайте **`API_SECRET`** (≥ 32 случайных символа) и отдельный `SESSION_SECRET`.
2. Включите HTTPS на обратном прокси: флаг `Secure` у cookie ставится, когда запрос пришёл по HTTPS (по `X-Forwarded-Proto` от прокси).
3. За прокси выставьте `TRUST_PROXY=1` и, если хопов несколько, `TRUSTED_PROXIES`.
4. Для продакшена используйте внешний PostgreSQL (`DATABASE_URL`), а не PGlite.
5. Оставьте CSP включённым (`DISABLE_CSP` не задан); если CDN добавляет свою CSP — убедитесь, что nonce не ломается.
6. Задайте `AI_DAILY_BUDGET` под свой тариф у провайдера.
7. Настройте мониторинг `GET /api/health?strict=1` и алерты (`ALERT_WEBHOOK_URL` / `ALERT_RECIPIENTS`).
8. Регулярно выполняйте `GET /api/backup` или включите `AUTO_BACKUP_HOURS`; храните `BACKUP_DIR` вне контейнера.
9. Обновляйте зависимости (Dependabot) и пересобирайте образ с `--build-arg GIT_SHA` — коммит виден в диагностике.

## Поддерживаемые версии

Поддерживается последняя версия ветки `main`. Исправления безопасности в старые версии не бэкпортируются.
