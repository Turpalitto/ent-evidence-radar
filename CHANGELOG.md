## [Unreleased]

### Added
- Полнотекстовый поиск PostgreSQL (`search_tsv`, GIN) с RU↔EN словарём ≈350 ЛОР-понятий, сортировкой по релевантности и подсветкой найденных термов (F-09, I-02, I-14).
- Асинхронное обновление: `POST /api/refresh` → `202 {runId}`, прогресс в `GET /api/runs/:id` (F-05, I-01).
- Ручные правки классификации (`overrides`) и скрытие записей (`isHidden`, `DELETE /api/articles/:id`), устойчивые к обновлениям и переклассификации (A-11).
- Связь препринт ↔ журнальная версия через `publishedDoi` medRxiv: одна запись вместо дубля, бейдж и +5 к доверию (A-05).
- Email-дайджест по расписанию из настроек: получатели, день/ежедневно, час, период, предпросмотр, «отправить сейчас» (A-09).
- Экран диагностики администратора `GET/POST /api/admin/diagnostics` и секция в настройках: версия/коммит, БД, лок, курсоры, источники, запуски, ИИ, метрики (A-12).
- Массовые операции `POST /api/articles/bulk`, кнопка «Страницу прочитано», подсказка «почему в ленте», пользовательские пресеты фильтров (I-14).
- Цитирование в один клик: Vancouver, ГОСТ Р 7.0.5-2008, BibTeX; экспорт CSV/RIS/BibTeX/JSON (A-13).
- Восстановление из бэкапа слиянием `POST /api/backup/restore`; автобэкапы с ротацией; pre-migration снимок (A-02, I-15).
- Health-check `GET /api/health` (`?strict=1`, `?metrics=1`), внутрипроцессные метрики, алерты в webhook/email при серии сбоев (I-08).
- Перепроверка отзывов (retractions) в PubMed батчами и версия классификатора с автоматической переразметкой (F-15, I-04).
- Корреляция запросов `x-request-id` в ответах, логах и ошибках 500 (I-07).
- Штатная остановка по SIGTERM/SIGINT: health 503 на время дренажа, прерывание идущего обновления со снятием блокировки, корректное закрытие PGlite; `NEXT_MANUAL_SIG_HANDLE=true` в Docker-образе; тики планировщика больше не накладываются.
- Europe PMC по темам (I-06): запрос каждой темы переводится из PubMed-синтаксиса (`src/lib/sources/epmc-query.ts`, перевод только расширяет выборку), найденное получает `topicId`; статус источника `degraded`, если часть тем упала; страховочный запрос — когда перевести нельзя ни одну тему. Описания источников по умолчанию обновляются при старте.
- PICO (A-10): блок «PICO» в карточке статьи и строка в тексте «Для консилиума» — из секций структурированной аннотации или эвристик по тексту (`src/lib/evidence/pico.ts`, 7 тестов + компонентный).
- Индексы (миграция 0015, `IF NOT EXISTS`): `fetched_at` для ленты «по сбору»/Atom, выражение `upper(nct_id)` для связи с реестром КИ и восстановления; GIN/btree индексы миграции 0002 объявлены в `schema.ts`; таблица индексов в `docs/ARCHITECTURE.md`.
- Типобезопасность: `noUncheckedIndexedAccess` для продакшн-кода (`tsconfig.strict.json`, входит в `npm run typecheck`); исправлено ~70 мест небезопасного доступа по индексу, в т. ч. горячие клавиши ленты при пустом списке, touch-обработчики без касаний, `count(*)`-агрегаты и парсинг заголовков прокси.
- Доступность: карточка статьи называется заголовком публикации, блокирует прокрутку страницы под собой (с компенсацией полосы прокрутки) и объявляет копирование/сохранение через live-регион; подписаны поле заметок, поиск (`type="search"`, роль searchbox) и поля формы тем.
- Публичные read-маршруты: `ETag`/`304` для `/api/articles`, `/api/articles/:id/related` и `/feed.xml` (+ `Last-Modified`/`If-Modified-Since` для читалок), мягкий rate-limit 240/мин и 60/10 мин с `Retry-After` (`src/lib/public-api.ts`, 10 тестов); OpenAPI описывает 304/429.
- Гигиена репозитория: `npm run check` (lint → typecheck → db:check → test), `CONTRIBUTING.md`, шаблоны PR и issue, `.editorconfig`.
- Отслеживание КИ (A-08): перепроверка записей ClinicalTrials.gov по NCT (статус, результаты, история в `trial_info`, миграция 0014), бейджи и блок реестра в карточке, строка журнала «КИ: статусы и результаты»; публикация по NCT занимает запись реестра (без дублей), слияние реестра с публикацией в одной пачке больше не превращает статью в `trial_registry`.
- Раздел руководств (A-06): орган-издатель руководства (`guideline_issuer`, миграция 0013, 30 органов), фасет-чипы издателей в ленте, фильтр `issuer=` в API/экспорте/RSS, бейдж на карточке; `CLASSIFIER_VERSION = 4`.
- Перепроверка отзывов по DOI через Crossref (A-04): записи без PMID (препринты, Europe PMC), expression of concern (−25 к доверию, бейдж), исправления (бейдж + ссылка на corrigendum); колонка `editorial_notice` (миграция 0012); обновление из источника не сбрасывает отзыв; отзыв из PubMed-перепроверки теперь тоже пересчитывает индекс доверия в том же запуске.
- Белый список журналов расширен до ~185 изданий (смежные Q1, национальные ЛОР-журналы MEDLINE/PMC, аудиология/фониатрия/сон, методологические); `CLASSIFIER_VERSION = 3` — сохранённые записи переразмечаются автоматически (I-05, частично).
- Компонентные тесты UI (jsdom + Testing Library) для ленты, карточки статьи и настроек; fixture-тесты адаптеров Europe PMC / ClinicalTrials.gov; сквозной тест раннера миграций (I-09).
- CI (lint, typecheck, drizzle check, тесты, build, docker smoke), Dependabot, `npm run db:migrate` с advisory-lock (I-10, I-15).
- Atom-лента с фильтрами — подписка на сохранённый поиск (`/feed.xml?subspecialty=…&design=…&minTrust=…`, `?topicId=`, `?q=`), ссылка «RSS для этого фильтра» в боковой панели.
- Документация: `docs/ARCHITECTURE.md`, `SECURITY.md`, `docs/openapi.yaml`, этот CHANGELOG (I-16, A-14).
- Офлайн-режим PWA (A-15): service worker `public/sw.js` (оболочка и статика — cache-first, публичные GET API — network-first с меткой `x-sw-cached-at`, лимит 80 записей, страница `/offline`), регистрация только в продакшене (`DISABLE_SW=1` отключает), очистка кэша API при выходе; в ленте — баннер офлайна/кэша по `navigator.onLine` и заголовкам ответа. Тесты: воркер в vm-песочнице (7), баннер ленты (2).
- Справочник журналов с ISSN (I-05): у ~175 из ~180 изданий белого списка указаны печатный и электронный ISSN (контрольные цифры проверяются тестом); PubMed и Europe PMC отдают ISSN записи (`articles.issns`, миграция 0016), сопоставление идёт ISSN → название, поэтому переименования и варианты написания больше не роняют уровень журнала. В README честно описано, что паттерны «хищнических» издательств на данных MEDLINE почти не срабатывают.

### Changed
- Авторизация: подписанная httpOnly-cookie после `/login`, Bearer / `X-API-Key` для скриптов, same-origin для изменяющих запросов (F-01).
- Классификатор v2: Cochrane и post-hoc анализы, ложные бонусы и субспециальности, размер выборки vs год, журналы по ISO-аббревиатурам; `CLASSIFIER_VERSION = 2` (F-06, F-07, F-11…F-13, F-33).
- Дедупликация по нормализованным идентификаторам (DOI → PMID → NCT → заголовок|год) с транзитивным слиянием внутри пачки (I-13).
- ИИ: общий суточный бюджет в БД, семафор, таймауты стрима, LRU-кэш; `POST /api/ai` принимает только `{articleId, action}` (F-08, F-23, F-24).
- medRxiv опрашивается по всему окну, а не первой странице (F-14).
- HTTP-слой источников уважает `Retry-After`, считает повторы и ошибки; мелкие находки F-26…F-32 (Atom `<author>`, лимиты полей тем, `/api/status` без внутренних деталей).
- Шрифты локальные — сборка не ходит в Google Fonts (F-04).
- Итоги на главной кэшируются 30 с с инвалидацией по событиям (I-11).
- Docker: процесс от `uid 1001`, `HEALTHCHECK`, `ARG GIT_SHA` для отображения коммита (F-17, A-12).

### Fixed
- Автосброс повреждённого PGlite больше не стирает данные молча — только при `PGLITE_RESET_ON_FAILURE=1` (F-02).
- Разбор PubMed XML со смешанным контентом (`<i>`, `<sup>`) не терял части аннотаций (F-03).
- Валидация входных данных всех API через zod; 400/404 вместо 500, единый формат `{error}` (F-10, I-07).
- CSV-экспорт экранирует формулы; дайджест рассылается через BCC (F-20, F-21).
- Статус PubMed «partial», если упала часть тем; гонка запросов и тройная загрузка ленты на маунте (F-18, F-19).
- Согласована схема drizzle и снапшоты миграций (`npm run db:check`) (F-16).
- Продакшен-сборка падала на `dns`/`net`/`tls`: клиентская карточка импортировала подписи статусов КИ из `@/lib/trials`, который тянет `@/db`. Подписи вынесены в `src/lib/evidence/trial-status.ts`; добавлен тест-страж границы клиент/сервер (обход графа импортов всех `"use client"`-файлов). Устранены предупреждения Turbopack о трассировке всего проекта из-за `readdir(BACKUP_DIR)`.
- `Cache-Control: no-store` из `next.config` перекрывал заголовки маршрутов: `ETag`/304 для `/api/articles` и `/api/articles/:id/related` не работали в браузере, а SSE `/api/ai` терял `no-transform`. Правило теперь исключает эти маршруты (тест на итоговые заголовки через path-to-regexp Next).

### Security
- Session cookie `httpOnly`/`SameSite=Lax`/`Secure`, rate-limit входа 10/10 мин, `timingSafeEqual` (F-01).
- CSP с nonce и `strict-dynamic`, согласованные `frame-ancestors 'none'` и `X-Frame-Options: DENY` (F-26).
- Доверие заголовкам прокси только при `TRUST_PROXY=1`; кросс-инстансный rate-limit (I-12).
- Обновлены уязвимые зависимости, `npm audit --omit=dev --audit-level=high` блокирует CI (F-22, I-10).
