# ENT Evidence Radar

Автоматический агрегатор доказательной научной литературы по **оториноларингологии** (ENT) из мировых источников:

- **PubMed / MEDLINE** (NCBI E-utilities) — MeSH-фильтрация, типы публикаций, Cochrane
- **Europe PMC** — REST API, дублирующий канал MEDLINE + препринты (SRC:PPR)
- **ClinicalTrials.gov** — API v2, интервенционные исследования, наличие результатов
- **medRxiv** — препринты категории Otolaryngology (с пометкой «без рецензии»)

Каждая запись автоматически классифицируется: **дизайн исследования** (СО/МА, РКИ, когорта, руководство…), **уровень доказательности** (Oxford 1–5), **размер выборки**, **субспециальности** и **индекс доверия** (0–100) на основе дизайна, уровня журнала, регистрации протокола, стандартов отчётности и признаков «хищнических» издательств.

> ⚠️ Инструмент для мониторинга литературы. Не является медицинской рекомендацией и не заменяет чтение первоисточников.

## Стек

- **Next.js 16** (App Router), React 19, TypeScript 5.9
- **Tailwind CSS v4**
- **Drizzle ORM 0.45** поверх **PostgreSQL**
- **PGlite** — встроенный PostgreSQL (wasm), БД «из коробки» без установки сервера
- **Vitest** — юнит-тесты ядра классификации

## Быстрый старт

```bash
npm install
npm run dev
```

Откройте http://localhost:3001 (или порт из вывода `next dev`).

По умолчанию используется **встроенный PGlite**: данные — в каталоге `./.pglite` рядом с проектом. Сервер сам создаёт БД, применяет миграции (`drizzle/`) и наполняет справочники (14 тем, источники, настройки). При первом запуске `instrumentation.ts` планирует автообновление (по умолчанию каждые 360 минут, настраивается в «Настройках»).

## Архитектура

```
src/
  app/            # App Router: страницы + REST API
  components/     # UI (Feed, Badges, ArticleDrawer, SettingsPanel, ...)
  db/             # подключение к БД (PGlite или PostgreSQL) + schema
  lib/
    evidence/     # classify.ts, journals.ts, taxonomy.ts  ← ядро (чистое, тестируемое)
    sources/      # адаптеры: pubmed, europepmc, clinicaltrials, medrxiv, http
    refresh.ts    # оркестрация сбора: source → dedup → classify → write
    queries.ts    # фильтры/поиск/пагинация статей
    defaults.ts   # 14 тем, настройки, источники
```

**Поток данных:** `instrumentation`/`POST /api/refresh` → `runRefresh` параллельно опрашивает источники → дедупликация (DOI → PMID → NCT → нормализованный заголовок) → `classify()` → запись в `articles` с `trust_breakdown`, `topic_ids`, `source_keys`. После записи выполняется **перепроверка отзывов**: PubMed проставляет тип «Retracted Publication» задним числом, поэтому флаг `isRetracted` у уже сохранённых статей периодически сверяется с PubMed (батчами по 200 PMID с уважением rate-limit); новые отзывы видны в журнале запусков как строка «Перепроверка отзывов». Записи **без PMID** (препринты medRxiv, Europe PMC) и **expression of concern** PubMed не покрывает — их закрывает вторая проверка через **Crossref** (`works?filter=updates:DOI`, пачками по 20 DOI, до 200 DOI за запуск по вращающемуся курсору; строка «Crossref: отзывы и EoC» в журнале). Найденное уведомление хранится в `editorial_notice` (тип, DOI уведомления, дата), отзыв/withdrawal ставит `isRetracted` (−60 к индексу доверия), expression of concern даёт −25 и оранжевый бейдж, исправление — жёлтый бейдж со ссылкой на текст corrigendum; обновление из источника эти флаги не сбрасывает. Контакт для polite pool Crossref — `CROSSREF_EMAIL` (по умолчанию `NCBI_EMAIL`).

**Версия классификатора.** Эвристики `classify()` (дизайн, уровень доказательности, trust score, tier журнала) со временем правятся; чтобы правки применялись и к уже сохранённым статьям, каждая запись хранит `classifier_version`, а записи со старой версией переразмечаются пакетами (до 2000 за запуск) в конце каждого обновления — строка «Переклассификация» в журнале. Принудительно: `GET /api/admin/reclassify` покажет, сколько записей ждут переразметки, `POST /api/admin/reclassify` (тело опционально: `{"force": true, "limit": 5000}`) выполнит её сразу. Пользовательские поля (прочитано, закладки, заметки, темы) переразметка не трогает.

**Производительность поиска:** полнотекстовый поиск идёт по генерируемой колонке `search_tsv` с GIN-индексом (миграция `0008`), поэтому даже на десятках тысяч записей запрос не превращается в seq scan; GIN-индексы `pg_trgm` из миграции `0003` остаются для префиксных фильтров по журналу/авторам. Подробности — `docs/ARCHITECTURE.md` (§5).

**Надёжность:** DB-лок `lock_refresh` в `settings` (+ внутрипроцессный мутекс) — без параллельных запусков даже между инстансами; изоляция сбоев источников (одна ошибка не обрывает весь запуск); уважение rate-limit NCBI; идемпотентный посев (`ensureSeeded`).

**Публичные интерфейсы и SEO:**
- `/feed.xml` — **Atom-лента** 60 последних публикаций: можно подписаться на радар из любой RSS/Atom-читалки. Ссылка объявлена в `<head>` всех страниц (`rel="alternate"`). Лента принимает те же фильтры, что и `/api/articles` (`?subspecialty=rhinology&design=rct&minTrust=70`, `?topicId=3`, `?q=tinnitus`…) — это **подписка на сохранённый поиск**: заголовок ленты описывает фильтры, ссылка «RSS для этого фильтра» есть в боковой панели. Персональные флаги (закладки, прочитано, скрытые) в публичную ленту не попадают. Ответ несёт `ETag` и `Last-Modified`: читалка, приславшая `If-None-Match`/`If-Modified-Since`, получает `304` без тела, пока сбор ничего не добавил; `/api/articles` тоже отвечает `ETag`/`304`. Публичные читающие маршруты прикрыты мягким rate-limit (см. `SECURITY.md`).
- `/sitemap.xml`, `/robots.txt` — для поисковых систем (API исключён из индексации).
- `/og.png` — брендовая карточка 1200×630 для превью ссылок (OpenGraph/Twitter).
- У каждой страницы свои `title`, `description`, `canonical` и `og:*` (см. `src/lib/metadata.ts`).
- `/api/health` — healthcheck для Docker/балансировщика.

## Развёртывание

### Docker (проще всего)

```bash
docker compose up -d --build
```

Приложение на http://localhost:3000. Данные (встроенный PGlite) — в `./docker-data`, резервные копии — в `./backups` (оба смонтированы как volume). Конфигурация через переменные окружения в `docker-compose.yml` (ключи AI, `API_SECRET`, `NCBI_API_KEY`); внешний PostgreSQL — раскомментируйте сервис `db` и `DATABASE_URL`.

> **Права на каталоги.** Процесс в контейнере работает от фиксированного `uid:gid 1001:1001`. При bind-mount с хоста
> один раз выполните `mkdir -p docker-data backups && sudo chown -R 1001:1001 docker-data backups`, иначе при первом
> старте будет `EACCES` на `.pglite`/бэкапах. Альтернатива без ручных прав — named volumes (закомментированный блок в `docker-compose.yml`).

Образ собирается в два этапа на базе `node:22-alpine`: standalone-сборка Next.js, непривилегированный пользователь `1001`, `HEALTHCHECK` по `/api/health` прямо в образе, volume для данных PGlite и бэкапов.

### Сам-хостинг (долгоживущий Node-процесс)

`instrumentation.ts` планирует автообновление внутри процесса — подходит для VPS/свой сервер. Запускайте с `NEXT_MANUAL_SIG_HANDLE=true`, чтобы остановка по SIGTERM корректно закрывала PGlite и снимала блокировку обновления (см. «Надёжность», п. 10).

### Serverless (Vercel) — внешний cron

`instrumentation` на serverless не жить. Используйте внешний расписатель — cron, GitHub Actions (`/.github/workflows/refresh.yml`) — который вызывает готовый эндпоинт:

```bash
curl -X POST https://<ваш-домен>/api/refresh \
  -H "Authorization: Bearer $API_SECRET"
# → 202 {"ok":true,"runId":123,"status":"running"} — запуск продолжается в фоне
curl https://<ваш-домен>/api/runs/123   # → {"ok":true,"run":{...,"status":"success"},"finished":true}
```

`POST /api/refresh` отвечает сразу (202 с `runId`), а сам сбор идёт в фоне — HTTP-соединение больше не держится 1–5 минут и не обрывается прокси. Прогресс по источникам пишется в журнал по ходу запуска; состояние — `GET /api/runs/:id` (так делает кнопка в интерфейсе и workflow `refresh.yml`). Если нужен старый синхронный режим (скрипты), добавьте `?wait=1`. Если запуск уже идёт — 409 с `runId` текущего. Состояние источников и последние ошибки — `GET /api/status`.

> На serverless фоновая задача живёт, пока платформа держит функцию (Next.js `after()`); на Vercel этого хватает
> для `maxDuration` функции. Если лимит платформы короче, чем запуск, — используйте `?wait=1` или self-host.

> Если на сервере задан `API_SECRET`, внешний расписатель обязан передавать его в заголовке
> `Authorization: Bearer …` (или `X-API-Key`) — иначе эндпоинт вернёт 401. В репозиторных
> GitHub Actions (`refresh.yml`, `digest.yml`) для этого нужны секреты `APP_URL` **и** `API_SECRET`.

## Поиск, экспорт и цитирование

- **Полнотекстовый поиск** — PostgreSQL FTS по генерируемой колонке `articles.search_tsv` (веса: заголовок A, аннотация B, журнал C, авторы D; GIN-индекс). Русские клинические термины расширяются англоязычными синонимами (`src/lib/search.ts`: «тонзиллэктомия» → tonsillectomy, «отит» → otitis media/otitis…), группы синонимов объединяются через OR, разные слова — через AND; по умолчанию при наличии запроса сортировка **по релевантности** (`ts_rank_cd`), есть режим «только в заголовке» (`scope=title`). Ответ `/api/articles` содержит `searchTerms` — по каким термам реально искали; интерфейс подсвечивает их в заголовках и аннотациях.
- **Экспорт выборки** — `GET /api/export?format=csv|ris|bibtex|json` с теми же фильтрами, что у ленты (до 2000 записей). RIS — для Zotero/EndNote/Mendeley, BibTeX — для LaTeX; CSV экранирует формулы (`= + - @`).
- **Ручные правки и скрытие** — в карточке можно исправить дизайн исследования и субспециальности (`PATCH /api/articles/:id` с `overrides`); правка хранится отдельно, классификатор применяет её поверх эвристик, поэтому обновление и переклассификация её не перетирают (бейдж «✎ вручную», уровень и индекс доверия пересчитываются). «Скрыть: не ЛОР / не по теме» (`isHidden`, он же `DELETE` без `?purge=1`) убирает запись из ленты, статистики, дайджеста и RSS, и она **не возвращается** при следующем обновлении; скрытые видны по флажку «Показать скрытые мной» (`hidden=1`). Правки и скрытия входят в бэкап и восстанавливаются.
- **Отслеживание клинических исследований** — сохранённые записи ClinicalTrials.gov перепроверяются по NCT (`filter.ids`, пачками по 100, до 300 за запуск по вращающемуся курсору; строка «КИ: статусы и результаты» в журнале). Смена статуса (например, «идёт набор» → «прекращено досрочно») и появление результатов фиксируются в `trial_info.events`, запись обновляется свежими данными реестра и переклассифицируется (с результатами — уже РКИ), а `fetched_at` сдвигается, чтобы изменение всплыло в ленте «по сбору» и в RSS; на карточке — бейдж «результаты опубликованы» / новый статус и блок «Реестр ClinicalTrials.gov» с историей. Публикация по тому же NCT (PubMed/Europe PMC) **занимает** запись реестра: та же строка становится статьёй (закладки, заметки и история КИ остаются), повторные записи реестра к ней лишь привязываются, а вторичные публикации по тому же NCT хранятся отдельно.
- **Руководства по издателю** — для записей с дизайном «руководство» классификатор определяет орган-издатель (`src/lib/evidence/guidelines.ts`: AAO-HNS, EPOS/EUFOREA, ICAR, ARIA, EAACI, AAAAI, ESPO, AAP, NICE, ENT UK, BSACI, AASM, ERS/ATS, IDSA, ASCO/ESMO/NCCN, ATA, AHNS, Bárány Society, ASHA/AAA, JCIH, IFOS, WHO, CDC, SIGN, SFORL, DGHNO/AWMF, Минздрав/НМАО) по заголовку, коллективным авторам, журналу и началу аннотации. Пресет «Руководства» показывает чипы издателей со счётчиками (ответ `/api/articles` содержит `issuers` при `design=guideline`), фильтр `issuer=<ключ>|other` работает в API, экспорте и RSS; на карточке — бейдж издателя.
- **Препринт ↔ журнальная версия** — medRxiv сообщает DOI рецензированной публикации (`publishedDoi`): препринт и его журнальная версия хранятся **одной записью** (в одной пачке сливаются; если журнальная версия уже в базе — препринт лишь добавляет источник/темы; если первым пришёл препринт — та же строка «дорастает» до журнальной статьи, заметки и закладки остаются). Пока журнальной версии нет в базе, карточка показывает бейдж «опубликован в журнале» и ссылку на DOI, а индекс доверия препринта получает +5.
- **Email-дайджест по расписанию** — в настройках: включить, получатели (до 50), день недели или ежедневно, час по времени сервера, период (1–60 дней); кнопки «Предпросмотр» (письмо показывается во встроенном окне) и «Отправить сейчас». Планировщик проверяет расписание раз в минуту, состояние последней отправки (`settings.digest_state`) защищает от повторов при нескольких инстансах и показывается в UI; без SMTP письмо формируется в dry-run.
- **Работа с лентой** — кнопка «✓✓ Страницу прочитано» помечает все непрочитанные записи на странице одним запросом (`POST /api/articles/bulk {ids≤200, isRead|isBookmarked|isHidden}`); в строке метаданных каждой карточки видны темы, по которым статья попала в ленту (подсказка «Почему в ленте» — темы и источники); свои комбинации фильтров можно сохранить как пресет («+ Сохранить фильтр», до 12, хранятся в `localStorage` браузера) и применять одним кликом рядом со встроенными.
- **Цитата в один клик** — в карточке статьи: Vancouver (ICMJE/NLM), ГОСТ Р 7.0.5-2008 и BibTeX (`src/lib/citation.ts`).
- **Корреляция запросов** — каждый ответ несёт `x-request-id` (принимается от доверенного прокси или генерируется); он же попадает в JSON-логи и в тело ошибок 500 — удобно искать инцидент в логах.

## Надёжность в продакшене

1. **Внешний PostgreSQL вместо PGlite.** PGlite хранит данные в файле рядом с проектом. При аварийном завершении процесса (OOM/kill) каталог `./.pglite` может повредиться — приложение само-восстановится, но потеряет данные, включая закладки и заметки. Для продакшена задайте `DATABASE_URL` и используйте внешний PostgreSQL.
2. **API-ключ NCBI (`NCBI_API_KEY`)** поднимает лимит E-utilities с 3 до 10 запросов/с — это ускоряет опрос PubMed и снижает шанс HTTP 429.
3. **Кросс-инстансная блокировка запуска.** Автообновление защищено не только внутрипроцессным мутексом, но и DB-локом (строка `lock_refresh` в `settings`): даже если запущено несколько инстансов или параллельно приходит внешний cron, рефреш выполнит только один из них — остальные получат `skipped`. Если процесс-«держатель» аварийно завершится, срок аренды (6 мин) истекает, и запуск продолжается автоматически.
4. **Изоляция ошибок источников.** Сбой одиночного источника не прерывает запуск: ошибка пишется в `source.lastStatus`/`lastError`, запуск получает статус `partial`, остальные источники продолжают сбор. Диагностика — `GET /api/status`.
5. **Serverless без своего cron.** `instrumentation.ts` живёт только в долгоживущем процессе. Если приложение хостится на serverless — внешний расписатель (GitHub Actions `refresh.yml`) по cron вызывает `POST /api/refresh` (нужны секреты `APP_URL` и, если задан `API_SECRET`, — `API_SECRET`).
6. **Health-check и алерты.** `GET /api/health` → `{ok, db, dbKind, version, uptimeSec, lastRun, refreshRunning, lockHolder, scheduler{started,alive,lastTickAt}, refreshStale, problems[]}`. Без параметров отвечает 200, пока доступна БД (для Docker/балансировщика). `?strict=1` — 503, если планировщик молчит > 3 мин, последний запуск упал или обновлений не было дольше 2× интервала (для внешнего мониторинга: UptimeRobot, Healthchecks.io и т. п.). `?metrics=1` (с авторизацией) добавляет внутрипроцессные счётчики запросов к NCBI/Europe PMC/CT.gov/medRxiv/ИИ, повторов, ошибок и длительностей, а также расход ИИ-бюджета. При `ALERT_FAILURES_THRESHOLD` (3) подряд упавших запусках уходит одно уведомление в `ALERT_WEBHOOK_URL` и/или на `ALERT_RECIPIENTS`, при восстановлении — ещё одно.
7. **Диагностика в один экран.** Настройки → «Диагностика (для администратора)» (`GET /api/admin/diagnostics`, только с авторизацией): версия и коммит (`GIT_SHA`, в Docker — `--build-arg GIT_SHA=$(git rev-parse HEAD)`), аптайм, часовой пояс, планировщик; движок и размер БД, счётчики (статьи/скрытые/закладки/правки/отозванные/ожидающие переклассификации); текущий запуск, держатель блокировки и остаток аренды (кнопка «Снять блокировку» — только если держатель погиб), курсор перепроверки отзывов (кнопка сброса), бэкапы, состояние дайджеста; статус и последняя ошибка каждого источника; 5 последних запусков; расход ИИ и счётчики HTTP; какие необязательные переменные окружения заданы (без значений).
8. **Миграции без простоя и без потерь.** При старте миграции применяются под `pg_advisory_lock` (несколько реплик не применяют одну миграцию одновременно); если есть новые миграции, сначала пишется снимок пользовательских данных `pre_migration_<дата>.json` в `BACKUP_DIR` — его можно загрузить через `POST /api/backup/restore`. Для контролируемого деплоя: `MIGRATE_ON_START=0` + `npm run db:migrate` отдельным шагом.
9. **Резервные копии и восстановление.** Экспорт — `GET /api/backup` (кнопка в настройках); восстановление — `POST /api/backup/restore` с тем же JSON (кнопка «Восстановить из файла»). Восстановление — **слияние**, а не перезапись: статьи сопоставляются по PMID → DOI → NCT, закладки/«прочитано» объединяются по ИЛИ, заметки дописываются блоком с датой бэкапа, темы создаются/обновляются по имени, настройки — только известные ключи с теми же границами, что в API. Статьи, которых ещё нет в базе, возвращаются в `unmatched` (появятся после обновления, если попадают в окно поиска). Долгоживущий процесс раз в `AUTO_BACKUP_HOURS` сам пишет `user_backup_<дата>.json` в `BACKUP_DIR` и хранит `BACKUP_KEEP` последних.
10. **Штатная остановка без последствий.** На `SIGTERM`/`SIGINT` (деплой, рестарт контейнера, Ctrl+C) приложение переводит `/api/health` в 503 (балансировщик перестаёт слать трафик), ждёт 1,5 с, прерывает идущее обновление — запуск помечается `failed` с причиной «процесс остановлен», кросс-процессная блокировка снимается сразу, а не через 6 минут аренды, — и закрывает PGlite/пул PostgreSQL. В Docker-образе задан `NEXT_MANUAL_SIG_HANDLE=true`, чтобы Next не завершил процесс раньше хуков; при запуске вне Docker добавьте эту переменную сами (`src/lib/shutdown.ts`).
11. **ИИ без сюрпризов в счёте.** Общий суточный бюджет вызовов провайдера (`AI_DAILY_BUDGET`) хранится в БД и действует на все инстансы; одновременных запросов не больше `AI_MAX_CONCURRENCY`; прогрев кэша выполняется только для открытой карточки и двух соседних. `POST /api/ai` принимает `{articleId, action}` — текст берётся из базы, поэтому через эндпоинт нельзя переводить произвольные тексты за ваш счёт. Зависший поток обрывается по таймауту простоя, обрезанный ответ помечается и не кэшируется.

## Тесты и CI

```bash
npm test
```

Покрыто ядро классификации: определение дизайна, уровень доказательности, размер выборки, субспециальности, индекс доверия, журнальные tier-ы, дедупликация. Также покрыты: парсер PubMed XML на реальных фрагментах (смешанный контент `<i>`/`<sup>`, сущности, секции аннотации, ретракции), кэш-ключи ИИ (коллизии префиксов), авторизация API (токены, сессионная cookie, отказ подделанным `Origin`/`Sec-Fetch-Site`, CSRF) и логика перепроверки отзывов.

Интеграционные тесты идут на PGlite in-memory: полный цикл запуска обновления с замоканными источниками (статусы `partial`/`degraded`, прогресс в журнале), восстановление из бэкапа (слияние по PMID/DOI/NCT), алерты по серии сбоев, бюджет/таймауты/LRU-кэш ИИ, полнотекстовый поиск с синонимами и релевантностью, дедупликация по нормализованным DOI/PMID/NCT (в т. ч. слияние препринта и журнальной версии внутри одной пачки), удаление темы с отвязкой статей, `Retry-After`/троттлинг HTTP-клиента, снимок данных перед миграцией, сквозной прогон `scripts/migrate.mjs`, штатная остановка (прерывание запуска со снятием блокировки), Atom-лента с фильтрами.

Адаптеры источников проверяются на фикстурах реальных ответов (PubMed XML, Europe PMC JSON, ClinicalTrials.gov API v2, страницы medRxiv). Контракт-тест сверяет `docs/openapi.yaml` с фактическими `route.ts` (пути, методы, `$ref`).

Компонентные тесты (`*.test.tsx`, среда jsdom + Testing Library, `fetch` замокан по маршрутам): лента — загрузка, фильтр и URL, «страницу прочитано», пользовательские пресеты, дебаунс поиска; карточка статьи — пометка прочитанным, закладка, Escape, ручные правки и скрытие, копирование цитат; настройки — переключатели, обработка 401, источники, диагностика.

На каждый push в `main` и PR запускается CI (`.github/workflows/ci.yml`): `npm audit --omit=dev --audit-level=high` → ESLint → `tsc --noEmit` → `drizzle-kit check` → Vitest → `next build`, затем отдельная job собирает Docker-образ и делает smoke-тест контейнера (`/api/health` отвечает, процесс работает от uid 1001). Dependabot (`.github/dependabot.yml`) еженедельно предлагает обновления npm-зависимостей (минорные/патчи — одним PR), ежемесячно — GitHub Actions и базового образа.
